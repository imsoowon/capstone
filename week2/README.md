# Week 02 — 최애주민 페르소나 멀티에이전트 시뮬레이션 (롯데시네마)

1주차에서 선정한 최애주민을 포함해 세 명의 가상 주민을 **4방향 캐릭터**로 시각화하고,
이들을 각각 독립된 **LLM 에이전트**로 만들어 가상 마을의 **롯데시네마**에서
"함께 볼 영화 한 편"을 두고 **대화·협상·합의**하게 한 소규모 멀티에이전트 시뮬레이션입니다.

검증 목표는 두 가지입니다.
1. 각 페르소나가 성격·말투·행동경향에 맞게 **반영**되는가
2. 페르소나 에이전트끼리 **유의미하게 소통**하는가

## ✅ 최종적으로 한 것

- **캐릭터화** — 전기태·이다연·인상훈을 정면/왼쪽/오른쪽/뒷모습 + 페르소나 카드로 제작 (`character_sheets.html`)
- **환경 설계** — 롯데시네마 무대(상영작 3편·상영관·가격·매점·예매수단)와 액션 `검색 / 방문 / 구매 / 대화`
- **멀티에이전트 시뮬레이션** — Colab에서 **Qwen2.5-3B(로컬)** 로 구동. 공유 로그로 서로의 말에 반응하며 3라운드 협상
- **합의 종결** — 협상 뒤 각자 최종 투표 → 만장일치/다수결로 "함께 볼 영화" 결정
- **자동 평가** — 심사 LLM이 인물별 반영도(1–5)·소통 유의미성(1–5)·합의결과 채점
- **3B 안정화** — JSON 파서 강건화, 한국어 전용 후처리(언어 누수 차단), 행동 반복 방지, 입장 고수 지침

## 📊 결과 (최종 실행 = 로컬 3B 기준)

- 세 주민이 서로 이름을 부르며 영화 취향을 **설득·협상**하는 대화가 형성됨
- 최종 투표에서 **다수결로 합의 도출** (예: '고요한 파도' 2/3표)
- 페르소나 반영도: 인상훈·이다연 4~5, 전기태 3~4 / 소통 유의미성 3

## ⚠️ 부족한 점 / 한계

이번 주차에서 **확실히 부족했던 점**을 정리한다.

1. **상용 API vs 3B 비교를 못 함.** 과제가 요구한 핵심 중 하나가 상용 API와 로컬 3B의 비교인데, Gemini 무료 티어 quota가 0(계정/지역 제한)으로 막혀 **로컬 3B로만** 실행했다. 페르소나 유지력·합의율의 정량 비교는 미완이다.
2. **3B 모델의 품질 한계.** 사투리·성격 일관성이 흐리고, 입장을 이유 없이 뒤집으며, 중국어·한자가 섞이는 언어 누수가 발생했다. 언어 누수는 후처리로, JSON 형식 붕괴는 파서로 **가렸을 뿐 근본 해결은 아니다.**
3. **환경이 단순 샌드박스다.** `검색`은 실제 웹이 아니라 고정 딕셔너리에서 답을 꺼내고, `방문·구매`도 상태 변수만 바꾼다. 실데이터·실서비스 연동이 없다.
4. **고정 턴 순서.** 인상훈→전기태→이다연 라운드로빈이라 실시간 끼어들기·반응형 대화가 아니고, 상호작용이 한 박자 늦다.
5. **1회성 정성 관찰.** 3인·3라운드 소규모이며, 여러 회차를 반복해 합의율·붕괴 사례를 **통계적으로 기록하지 않았다.**
6. **평가의 신뢰도 제한.** 심사자도 동일한 3B라 사실상 자기평가에 가깝고, 점수의 객관성이 낮다.
7. **합의가 억지 종결에 가깝다.** 자연 합의가 아니라 마지막 라운드 압박 + 다수결 투표라는 **장치로 강제 종결**한 결과다.
