# 홍대 상권 방문 시뮬레이션 (캡스톤 논문실험 3)

페르소나 기반 LLM 방문 시뮬레이션이 **홍대입구역** 실제 유동인구 분포(연령·성별·시간대·요일)를 얼마나 재현하는지 검증한 실험입니다. 동대문패션타운·이태원 실험(`캡스톤_논문실험`, `캡스톤_논문실험2`)과 동일한 2단계 프롬프트 방법론을 사용했고, Google Colab 노트북 하나로 "1단계 상권 설명 입력 → 2단계 방문판단 → 실제 유동인구와 비교"까지 한 번에 실행됩니다.

- 결과 정리: 아래 [결과](#2단계-시뮬레이션-결과-vs-실제-n150) 섹션, 원본 수치는 `hongdae_stage2_final_comparison_500.csv` / `hongdae_normalization_and_stage2_effect.csv`
- 실행 노트북: [`hongdae_simulation_gemini.ipynb`](./hongdae_simulation_gemini.ipynb)

## 실행한 것

동대문·이태원 실험은 스크립트를 여러 개(1~5번) 나눠 실행했지만, 이 실험은 **Colab 노트북 하나**로 아래 과정을 순서대로 실행합니다(12개 코드 셀).

**동대문·이태원과의 방법론 차이 두 가지**:
1. LLM을 OpenAI GPT 계열(`gpt-5-mini`) 대신 **Google Gemini 무료 티어**(`gemini-3.5-flash-lite`)로 바꿨습니다. API 키가 없어서 무료로 반복 호출 가능한 쪽을 택했습니다.
2. 숙제 요구사항에 따라 **베이스라인 비교**를 추가했습니다 — 2단계(LLM 방문판단) 없이 페르소나 풀에서 그냥 무작위로 뽑았을 때의 분포를 실제값과 비교해서, "2단계 판단 자체가 정확도를 얼마나 개선/악화시키는지"를 분리했습니다. 동대문·이태원 실험에는 이 비교가 없었습니다.

## 페르소나 표현

`nvidia/Nemotron-Personas-Korea`(100만 명)에서 무작위로 뽑은 각 인물을 아래 4개 필드로 압축해 2단계 프롬프트에 넣습니다(동대문 실험의 5개 필드와 달리 **거주지는 제외**하고 나이/성별/직업/취미·성향만 사용).

```python
def get_persona_text(p):
    fields = ["persona", "travel_persona", "culinary_persona",
              "hobbies_and_interests", "professional_persona"]
    text = []
    for field in fields:
        value = p.get(field)
        if value:
            text.append(f"{field}: {value}")
    return "\n".join(text)[:5000]

people.append({
    "index": i,
    "나이": p.get("age"),
    "성별": p.get("sex"),
    "직업": p.get("occupation"),
    "취미·성향": get_persona_text(p)   # persona/travel/culinary/hobbies/professional 필드를 합친 텍스트
})
```

## 2단계 프롬프트 설계 상세

동대문·이태원 실험과 동일하게, 프롬프트는 페르소나가 방문 여부·시간대·요일을 **실제 통계에 맞추려 하지 말고 스스로의 성향에 비추어 추론**하도록 명시적으로 지시합니다(편향 방지 문구).

```
[상권 정보]
{HONGDAE_INFO를 JSON으로}

[가상 인물]
{나이·성별·직업·취미·성향을 담은 인물 10명을 JSON 배열로}

위 '상권 정보'와 '인물 특성'을 함께 고려해,
각 인물이 향후 30일 내 이 상권을 방문할지 판단하세요.

방문한다면 주로 몇 시경인지와 어느 요일에 방문할지도 판단하세요.

※ 상권 정보는 '이곳이 어떤 장소인지'에 대한 설명일 뿐입니다.
인물의 성향에 비추어 방문 여부와 시간대를 스스로 추론하세요.

실제 방문객의 연령·성별·시간대·요일별 분포나
유동인구 통계를 맞추려고 하지 마세요.

각 인물은 서로 독립적으로 판단하세요.

[출력 — JSON 배열만]

[
  {
    "index": 0,
    "방문": "예 또는 아니오",
    "주요_시간대": "00-06|06-11|11-14|14-17|17-21|21-24 또는 null",
    "주요_요일": "월|화|수|목|금|토|일 또는 null",
    "이유": "간단한 판단 이유"
  }
]
```

인물 10명씩 배치(`BATCH_SIZE = 10`)로 호출하며, "방문"으로 판단된 인물이 150명(`TARGET_VISITORS`) 모일 때까지 반복합니다. 실제 실행에서는 총 531명을 평가해 150명이 방문 판정을 받았습니다(**수락률 28.25%**).

## LLM 및 실행 환경

| 항목 | 값 |
|---|---|
| 플랫폼 | Google Colab |
| LLM | Google Gemini `gemini-3.5-flash-lite` (무료 티어) |
| 호출 방식 | 배치당 10명, 호출 간 최소 15초 대기 + 429 발생 시 지수 백오프(최대 60초, 최대 6회 재시도) |
| 페르소나 풀 | `nvidia/Nemotron-Personas-Korea` (HuggingFace, 100만 명), `SEED = 42`로 셔플 |
| 목표 방문자 수 | 150명 (`TARGET_VISITORS`) |
| 베이스라인 표본 수 | 150명 (`BASELINE_N`, 방문자 수와 항상 동일하게 자동 동기화) |

동대문·이태원은 OpenAI GPT 계열(`gpt-5-mini`)을 사용했지만, 이 실험은 API 키가 없어 무료 티어를 반복 호출할 수 있는 Gemini로 대체했습니다. 그래서 이 실험의 절대 오차 수치를 동대문·이태원과 "완전히 같은 조건"으로 비교하기는 어렵고, 홍대 자체의 경향과 이미 다른 두 실험에서 드러난 패턴이 모델·상권이 바뀌어도 재현되는지를 보는 데 의미가 있습니다.

## 실행 방법

1. `hongdae_simulation_gemini.ipynb`를 Google Colab에서 엽니다.
2. [Google AI Studio](https://aistudio.google.com/)에서 Gemini API 키를 발급받습니다.
3. Colab 왼쪽 열쇠 아이콘(보안 비밀/Secrets)에 이름 `GEMINI_API_KEY`로 키를 등록하고, 노트북 접근을 허용합니다.
4. 셀을 위에서부터 순서대로 실행합니다. 두 번째 코드 셀(`code-2`)에서 실제 유동인구 CSV 업로드 창이 뜨면 `hongdae_actual_20261_hongdaeipgu.csv`(또는 서울열린데이터광장 원본 전체 파일)를 업로드합니다.
5. 2단계 셀(`code-7`)이 방문자 150명을 채울 때까지 자동으로 반복 호출합니다 — 호출 간격(15초) 때문에 시간이 다소 걸립니다. 429 오류가 계속 뜨면 [aistudio.google.com/rate-limit](https://aistudio.google.com/rate-limit)에서 본인 프로젝트의 실제 한도를 확인하고 `MIN_SECONDS_BETWEEN_CALLS`를 늘리세요.
6. 마지막 셀까지 실행하면 비교 표와 MAE, 결과 CSV 5종이 생성됩니다.

## 실제 유동인구 분포 (기준값)

| 축 | 분포 |
|---|---|
| 성별 | 남 47.35% / 여 52.65% |
| 연령대(원본, 10대 포함) | 10대 15.05% · 20대 41.97% · 30대 19.35% · 40대 10.97% · 50대 6.85% · 60대+ 5.81% |
| 연령대(10대 제외 정규화) | 20대 49.41% · 30대 22.78% · 40대 12.92% · 50대 8.06% · 60대+ 6.84% |
| 시간대 | 00-06 18.60% · 06-11 12.99% · 11-14 13.29% · 14-17 17.00% · 17-21 24.43% · 21-24 13.70% |
| 요일 | 월 12.58% · 화 12.38% · 수 12.93% · 목 13.54% · 금 14.91% · 토 18.08% · 일 15.57% |

동대문·이태원과 달리 홍대는 20대 비중이 압도적으로 높고(원본 41.97%, 정규화 후 49.41%), 요일별 분포는 토요일(18.08%)이 가장 높지만 다른 상권만큼 극단적으로 몰려 있지는 않습니다(평일도 12~15%대로 고르게 분포).

## 2단계 시뮬레이션 결과 vs 실제 (n=150)

| 항목 | MAE(%p) |
|---|---|
| 연령대(10대 제외) | 6.66 |
| 성별 | 5.35 |
| 시간대 | 14.87 |
| 요일 | 17.24 |

## 베이스라인 대조실험 (2단계 유무 비교)

베이스라인은 2단계 질의 없이 페르소나 풀에서 무작위로 150명을 뽑은, LLM 판단을 전혀 거치지 않은 표본입니다(시간대·요일은 정의되지 않아 연령·성별만 비교).

| 지표 | 베이스라인 MAE(%p) | 2단계 MAE(%p) | 변화 |
|---|---|---|---|
| 연령대(10대 제외) | 19.48 | 6.66 | **-12.81%p (2단계가 크게 개선)** |
| 성별 | 3.31 | 5.35 | **+2.04%p (2단계가 오히려 악화)** |

**연령대**: 무작위 인구 표본은 홍대 실제 방문객의 20대 쏠림(49.41%)을 전혀 반영하지 못하는 반면(베이스라인 20대 비중 12.75%), 2단계는 "젊은 문화·유흥 상권"이라는 상권 특성을 반영해 20대 비중을 훨씬 높게 추정했습니다(35.42%). 2단계 판단이 명확하게 가치를 더한 지표입니다.

**성별**: 반대로 무작위 표본 자체가 이미 실제 성비(남 47.35%/여 52.65%)에 가까웠는데(베이스라인 남 50.67%/여 49.33%, MAE 3.31), 2단계는 여성 비중을 58%까지 끌어올려 오차가 오히려 커졌습니다(MAE 5.35). "카페·데이트·쇼핑" 등 방문목적 문구가 여성 쪽으로 약한 연상을 만들었을 가능성이 있으며, 동대문 실험에서 상권 정보 추가 시 성별 오차가 커졌던 것과 유사한 성격의 부작용으로 보입니다.

## 종합 결론

1. **연령대·성별은 비교적 잘 재현되고, 시간대·요일은 잘 재현되지 않는다.** 동대문패션타운·이태원 실험과 동일한 패턴이며, LLM 모델(GPT → Gemini)이 바뀌어도 재현되는 것으로 보아 모델 특성이 아니라 "상권 방문 여부·시간을 LLM에게 묻는" 과제 구조 자체에서 비롯된 경향일 가능성이 있습니다.
2. **요일 오차의 근본 원인도 동일하게 재현됨.** 평일 방문이 0%로 수렴하고 토요일에 과대 쏠림(74% vs 실제 18.08%)이 나타난 것은 동대문 실험이 제시한 "상권 방문 질문 자체가 주말 나들이를 연상시킨다"는 가설과 일치합니다.
3. **10대 제외 정규화는 이번에도 오차를 유의미하게 줄이지 못했다.** 다만 홍대는 10대 비중이 커서(15.05%), "10대 비중이 작아서 정규화 효과가 없다"는 기존 설명만으로는 부족하며 추가 원인 분석이 필요합니다.
4. **2단계(LLM 방문판단)의 효과는 지표마다 다르다.** 연령대처럼 상권 특성과 인구통계가 강하게 연결된 지표는 2단계가 베이스라인 대비 크게 개선하지만(-12.81%p), 성별처럼 원래 무작위 표본이 이미 실제에 가까웠던 지표는 2단계가 오히려 악화시켰다(+2.04%p). 즉 2단계 추론이 "항상 도움이 되는" 것은 아니며, 상권 설명 문구가 만드는 연상 편향이 지표별로 다르게 작용합니다.

## 한계

- 표본 크기가 n=150으로 동대문·이태원의 n=500보다 작아, 수치의 안정성은 다소 낮을 수 있습니다. 무료 티어 한도 때문에 n=500 재실행은 하지 못했습니다.
