# 08 · 홍대입구역(홍대) 상권 신규 출점 시뮬레이터

`index.html` 하나로 열리는 도시 시뮬레이터입니다(데이터·코드·이미지 포함, 약 6.6MB). 공군호텔 버전(07)과 같은 구조로, 대상 상권만 **홍대입구역(홍대), 상권코드 3120103**으로 바꿨습니다. 그리고 페르소나를 **실행할 때마다 Nemotron-Personas-Korea 100만 명 중에서 무작위로 불러오도록** 했습니다.

**결론.** 롯데그룹 계열 세븐일레븐의 추가 출점은 **조건부 보류**입니다. 실사를 한다면 **C(홍대입구역 9번 출구 앞)를 먼저**, A(서교동 서측 공백 골목)를 대안으로 봅니다. C는 방문 수와 브랜드 순증이 모두 가장 컸습니다. 다만 방문의 약 25%는 기존 세븐일레븐에서 옮겨 온 자기잠식이었습니다.

---

## 1. 바뀐 점 (07 공군호텔 → 08 홍대)

| 항목 | 07 공군호텔 | 08 홍대입구역(홍대) |
|---|---|---|
| 상권 | 3110815 골목상권, 18.3만㎡ | 3120103 발달상권, 46.2만㎡ |
| 경계 안 편의점 | 8곳 | **30곳 (세븐일레븐 7, GS25 11, CU 8, 이마트24 2, 기타 2)** |
| 출발 역 | 대방역 | 홍대입구·합정·상수역 출입구 18곳 |
| 페르소나 | 내장 3,961명 고정 풀 | **실시간 무작위 추출(100만 명)** + 내장 4,163명 대체 풀 |
| 반복 비교 | 후보 방문·점유 | + **세븐일레븐 순증·자기잠식** (후보 없는 날과 쌍대 비교) |
| 길찾기 | O(n²) Dijkstra | 이진 힙 Dijkstra (그래프 3,000노드) |
| 건물 | Overture 1,585동 | OSM 5,346동 (층수 등록 613동) |

## 2. 페르소나 실시간 랜덤 추출

- 사이드바의 **페르소나 출처**가 기본값 “Nemotron 100만 명에서 실시간 무작위”입니다.
- **새 페르소나로 실행 ↻**을 누르면 새 시드가 생깁니다. 시드로 무작위 오프셋을 정한 뒤 HuggingFace datasets-server(`/rows`, 100행씩)에서 20세 이상만 골라 N명(100·200·400)을 불러옵니다.
- **같은 시드를 넣으면 같은 사람을 다시 불러옵니다.** 발표나 보고서에서 같은 결과를 재현할 수 있습니다.
- 네트워크가 막혔거나 요청 한도(429)에 걸리면 세 번 재시도합니다. 그래도 실패하면 내장 풀(4,163명)로 자동 대체합니다. 결과 패널에 `실시간` / `내장 풀(대체)`로 표시됩니다.
- 반복 비교(50~300일)는 매일 요청하면 너무 느려서 내장 풀을 씁니다.
- 방문 성향 키워드(긍정 13개·부정 7개·업종 키워드)는 `PERSONAS.meta`에 명시했습니다. 실시간으로 불러온 사람과 내장 풀이 같은 규칙으로 점수를 받습니다. 1단계 노트북의 원래 키워드 목록은 이 HTML에 남아 있지 않아 이번에 다시 정의했습니다.

## 4. 후보와 결과

| 후보 | 위치 | 역 출구 | 최근접 세븐일레븐 | 200m 내 편의점 |
|---|---|---|---|---|
| A | 서교동 서측 생활 골목 (양화로12길) | 합정역 2번 137m | 357m | 3곳 |
| B | 홍대 중심가 남측 골목 (와우산로22길) | 상수역 2번 443m | 202m | 7곳 |
| C | 홍대입구역 9번 출구 앞 (양화로 남측) | 47m | 162m | 9곳 |

후보는 경계 안 보행 그래프 노드마다 세븐일레븐·편의점 거리, 역 출구 거리를 계산해서 골랐습니다. A는 세븐일레븐 공백이 가장 큰 구간, B는 중심가 안쪽 공백 구간, C는 역세권 대조군입니다.

**반복 비교 (400명 × 300일, 매력도 ×1.0, 시작 시드 20261009, 쌍대 비교)**

| 후보 | 하루 후보 방문 | 편의점 점유 | 세븐일레븐 순증 | 자기잠식 |
|---|---:|---:|---:|---:|
| A | 0.91명 | 3.4% | 0.71명 | 21% |
| B | 0.49명 | 1.9% | 0.30명 | 40% |
| **C** | **1.29명** | **4.9%** | **0.97명** | 25% |

매력도를 ×1.5로 올려도 순위는 C > A > B로 같았습니다(순증 1.36 / 0.97 / 0.46명). 이 값은 표본 인원 기준의 상대 비교입니다. 실제 상권 인구로 확대한 매출 예측이 아닙니다.

**손익 계산기**(가정): 점포 앞 통행 3,000 / 5,000 / 8,000회, 월 고정비 1,200만원으로 두면 월 영업잉여는 보수 −615만원, 기준 +250만원, 낙관 +2,040만원입니다. 홍대의 통행량·임대료 실측이 결론을 좌우합니다.

## 5. 한계

- 점포 좌표는 OSM 등록 자료입니다. 영업·폐업 여부는 현장 확인이 필요합니다. 상권 경계는 2023 배포본입니다.
- 방문확률·시간대·업종 선호는 1단계 상식 규칙입니다. 그래서 시뮬레이션 방문자의 20대 비중(약 25%)이 실제(49%)보다 낮고, 숙박 업종 비중이 높게 나옵니다.
- 페르소나는 전국 인구라 관광객·외국인이 없습니다. 홍대의 핵심 수요 일부가 빠져 있습니다.
- 07 버전의 LLM 에이전트 교차검증(Groq)은 이번 버전에서 실행하지 않았습니다. `DATA.llm`을 채우면 기존 패널이 그대로 표시됩니다.
- 실시간 추출은 HuggingFace 공개 API의 가용성·요청 한도에 의존합니다.

## 6. 도구

Python(shapely, pyproj, pyshp, networkx), Playwright/Chromium(브라우저 검증·대표 이미지), 순수 HTML/CSS/JS + Canvas 2D. 라이선스: OSM(ODbL), 서울시(공공누리 1유형), Nemotron-Personas-Korea(CC BY 4.0), 위성사진(Esri).

**검증.** JS 오류 0건. 모든 도보 경로가 그래프의 연결된 간선만 따릅니다. 데스크톱과 모바일(390px)에서 가로 넘침이 없습니다. 오프라인일 때 내장 풀로 대체되는 것을 확인했습니다.
